# Comets on the Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Comets bright enough for binoculars (and, optionally, telescopes) appear on the Calendar as "arrives / at its best / last look" events, from live Minor Planet Center data.

**Architecture:** A pure orbit module turns MPC's one-line comet elements into positions and predicted magnitudes. A pure season module scans nights from the start of the current month to 12 months ahead and returns up to three events per comet for a place. A small store fetches and caches the data in the browser; the existing synchronous calendar engine reads the store, and its cache key includes a store version so everything recomputes when comets arrive.

**Tech Stack:** React 19, Vite, astronomy-engine (already installed), Vitest, oxlint. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-23-comets-design.md`

## Global Constraints

- Data URL: `https://www.minorplanetcenter.net/iau/MPCORB/CometEls.txt`; cache key `starling.comets` in `localStorage`, holding `{ text, fetchedAt }`; refresh after 24 hours; on a failed fetch use any cached copy regardless of age.
- Magnitude: `m = H + 5·log10(Δ) + 2.5·G·log10(r)`.
- Eyes and binoculars: magnitude ≤ 8, Sun below −12°. Telescope comets: 8 < magnitude ≤ 11, Sun below −18°. Comet at least 10° high, for at least 30 minutes of the night. `Naked eye` tag at best magnitude ≤ 6; `Telescope` tag on telescope comets.
- Span: start of the current month (in the place's time zone) to 12 months ahead. No comet events outside it.
- Kinds: group `{ id: 'comet', name: 'Comets' }`; kinds `{ id: 'comet', group: 'comet', name: 'Eyes and binoculars', on: true }` and `{ id: 'telescope-comet', group: 'comet', name: 'Telescope comets', on: false }`.
- Copy, verbatim: "No bright comets expected right now. New ones show up here on their own." and "Comet predictions couldn't load right now."
- Event names: `Comet X arrives`, `Comet X at its best`, `Last look at Comet X`; phone `tiny` is the bare name (`Lemmon`).
- Code style: section headers like `// SETTINGS` and `/* PAGE */` separated by 3 blank lines, no other comments, minimal classes. Lint is `npm run lint` (oxlint) and must report 0 warnings; tests are `npx vitest run`.
- Accessibility: nothing new conveyed by color alone; the checklist note is real text.
- Don't commit; the user reviews and commits. Each task ends with tests and lint passing and changes left uncommitted.

## Review Focus

1. A shared link to a comet event (`?event=comet-…`) opened before comet data has loaded should still open the card once comets arrive. Test in Task 4.
2. The MPC site is down and nothing is cached: no crash, no comets, and the checklist note says predictions couldn't load. Test in Task 3.
3. `localStorage` throws (private mode, blocked storage): comets still load and work for the visit. Test in Task 3.
4. Near-parabolic (e ≈ 1) and hyperbolic (e > 1) orbits give finite positions, never `NaN`. Test in Task 1.
5. Changing location after comets loaded recomputes comet events for the new place. Test in Task 2.

### Task 1: Orbit and brightness

**Files:**
- Create: `src/sky/calendar/cometOrbit.js`
- Test: `src/sky/calendar/cometOrbit.test.js`

**Interfaces:**
- Produces:
  - `parseComets(text: string) -> Comet[]` where `Comet = { id, designation, name, perihelion: Date, q, e, peri, node, incl, H, G }` (angles in degrees, J2000 ecliptic). `id` is the packed designation from columns 1–12, trimmed, made URL-safe (e.g. `CK25A060`). `name` is the familiar name: the text in parentheses for non-periodic comets (`C/2025 A6 (Lemmon)` → `Lemmon`), the part after `P/` for periodic ones (`161P/Hartley-IRAS` → `Hartley-IRAS`), else the designation. Lines without a numeric H are skipped.
  - `cometPlace(comet: Comet, date: Date) -> { vector: {x,y,z}, r: number, delta: number }`: geocentric J2000 equatorial vector in AU, Sun distance r, Earth distance delta.
  - `cometMagnitude(comet: Comet, r: number, delta: number) -> number`.

Fixed-width columns (0-based `slice`, verified against today's file): perihelion year `14,18`, month `19,21`, day `22,29` (TT, fractional), q `30,39`, e `41,49`, argument of perihelion `51,59`, node `61,69`, inclination `71,79`, H `91,95`, G `96,100`, designation and name `102,158`.

### Task 2: Comet season events

**Files:**
- Create: `src/sky/calendar/cometEvents.js`, `src/sky/calendar/cometSample.js`
- Modify: `src/sky/calendar/kinds.js` (group and two kinds from Global Constraints; the comet group goes last)
- Test: `src/sky/calendar/cometEvents.test.js`

**Interfaces:**
- Consumes: Task 1's `parseComets`, `cometPlace`, `cometMagnitude`; `skyTools.js` (`horizon`, `dayKey`, `nightKey`, `timeWord`, `windowWords`, `brightness`, `moonLit`, `DAY`, `HOUR`, `MINUTE`); `localNoon`, `localParts` from `../night.js`; `clock`, `where` from `../words.js`.
- Produces:
  - `cometSeason(comets: Comet[], place, now: Date) -> Event[]`: all comet events for the span (start of `now`'s month in `place.timeZone` to 12 months later). Pure; cached in a module `Map` keyed by place, `monthKey` of `now`, and `comets` identity.
  - `SAMPLE_COMETS: Comet[]` in `cometSample.js`: four made-up comets (already-parsed objects, not text) whose seasons fall between December 2026 and June 2027 for Kansas City: "Starling" (best about magnitude 5, naked eye), "Finch" (best about 7), "Wren" (best about 10, telescope), and "Southwind" (bright but always below −50° declination). Tune elements so the expectations in this task's tests hold.

Display name: `Comet ${comet.name}`; if two comets with events in the same season share a name (several are called "Lemmon"), add the designation: `Comet Lemmon (C/2025 A6)`.

Event shape, same as other kinds: `{ id, kinds, group: 'comet', date, day, time, here, where, icon: 'comet', short, tiny, name, tags, note, rows }`. `id` is stable across data refreshes: `comet-${comet.id}-${phase}` with phase `arrives | best | last`.

Night scan: for each local night in the span, sample every 30 minutes from local noon + 4 h to local noon + 20 h (same pattern as `coreNight` in `starEvents.js`). A sample counts for eyes-and-binoculars if magnitude ≤ 8, Sun < −12°, comet ≥ 10° high; for telescope if magnitude ≤ 11, Sun < −18°, comet ≥ 10° high. A night is visible for a class with ≥ 2 such samples (30 minutes). Pre-filter: skip comets whose magnitude, checked weekly through the span from Earth's center, never reaches 11.

Kind: `comet` if any night is binocular-visible, using those nights; otherwise `telescope-comet` using telescope-visible nights. Phases per spec: arrives (skip if the first night of the span is visible), best (brightest predicted magnitude among visible nights), last (skip if the last night of the span is visible); one visible night gives only best. Day placement: `timeWord(window) === 'Before dawn'` → `dayKey`, else `nightKey`, as in `viewed()`.

Rows: `['Best seen', windowWords(window)]`, `['Look', where(alt, az) + ' around ' + clock(best)]`, `['Brightness', brightness(mag) + ' (predicted)']`, `['In', constellation]`, `['Moon', moonLit(best)]`. Note: `Predicted to reach magnitude 6.5: …` with the spec's warning that forecasts are often off.

Worldwide: no visible nights here, but the comet reaches the class limit somewhere in the span while ≥ 20° from the Sun → one `best` event with `here: false` and `where` "Best seen from the Southern Hemisphere." when the place is north and the comet's declination at best is below 0, "Best seen from the Northern Hemisphere." for the reverse, otherwise "Not visible from here after dark."

### Task 3: Loading and caching comet data

**Files:**
- Create: `src/sky/calendar/cometStore.js`, `src/sky/calendar/useComets.js`
- Test: `src/sky/calendar/cometStore.test.js`

**Interfaces:**
- Consumes: Task 1's `parseComets`; Task 2's `SAMPLE_COMETS`.
- Produces:
  - `loadComets({ fetcher = fetch, storage = localStorage, now = new Date() }) -> Promise<{ comets: Comet[], status: 'ready' | 'failed' }>`: uses a cached copy younger than 24 hours without fetching; otherwise fetches; saves `{ text, fetchedAt }`; on failure falls back to any cached copy (`status: 'ready'`), else `{ comets: [], status: 'failed' }`. Storage read/write errors are caught and ignored.
  - Store: `cometState() -> { comets, status: 'loading' | 'ready' | 'failed', version: number, now: Date }`; `setCometState(next)` bumps `version`; `subscribeComets(listener) -> unsubscribe`.
  - `useComets() -> { status, version }` (React hook): on first use anywhere, starts `loadComets` once and puts the result in the store; re-renders on changes. In development (`import.meta.env.DEV`) with `?comets=sample` in the URL, uses `SAMPLE_COMETS` and status `ready` without fetching.
